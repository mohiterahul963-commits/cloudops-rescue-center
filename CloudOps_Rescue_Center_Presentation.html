Project Presentation01

1. Project Overview

What is it?

A microservices-based incident management application designed to receive incidents and process notifications.

Architecture

The application contains separate services for incident management and notification processing.

Deployment

Services are containerized using Docker and deployed on a Kubernetes cluster using Minikube.

Communication

Incident API communicates with Notification Service through Kubernetes Service DNS.

CloudOps Rescue Center02

2. Problem Statement

IT teams need a simple way to record application incidents and trigger notification processing.

  • Incidents should be created through an API.
  • Each incident should contain ID, title, severity and status.
  • A notification process should be triggered when an incident is created.
  • The services should be independently deployable and containerized.
  • The application should run reliably inside Kubernetes.
CloudOps Rescue Center03

3. Project Objective

  • Build a Python Flask Incident Management API.
  • Create a separate Notification Service.
  • Containerize both services with Docker.
  • Enable service-to-service communication.
  • Deploy both services using Kubernetes.
  • Expose the Incident API using a Kubernetes NodePort.
  • Test the complete incident-to-notification workflow.

6. Incident API

Port: 5000

  • GET / — confirms the API is running.
  • GET /health — health check endpoint.
  • GET /incidents — returns incident records.
  • POST /incidents — creates a new incident.

Example incident fields: ID, Title, Severity, Status

CloudOps Rescue Center07

7. Notification Service

Port: 5001

  • Runs as an independent microservice.
  • Receives requests from the Incident API.
  • Processes the notification request.
  • Returns a success response to the Incident API.

Response: Notification processed successfully
